# ARCHITECTURE.md

## Overview

The portfolio is organized as a frontend/backend web application.

The frontend contains:
- Public portfolio pages.
- Administrative dashboard.
- JavaScript modules for API access, rendering, localization, and administration.

The backend contains:
- FastAPI application.
- SQLAlchemy models.
- Pydantic schemas.
- Service/business logic.
- API routers.
- Authentication-related functionality.

## Content Architecture

The main content resources are:

1. Projects
2. Skills
3. Experiences

### Projects

Projects contain portfolio work displayed publicly when published.

The admin dashboard supports:
- Listing projects.
- Creating projects.
- Editing projects.
- Deleting projects.
- Publication state.
- Stack information.
- Repository URL.
- Demo URL.
- Image path.
- Portuguese and English descriptions.

### Skills

Skills contain technical technologies grouped by category.

The admin dashboard supports:
- Listing skills.
- Creating skills.
- Editing skills.
- Deleting skills.
- Category.
- Name.
- Display order.

### Experiences

Experience is implemented as a separate content resource.

The backend includes:

- `backend/app/models/experience.py`
- `backend/app/schemas/experience.py`
- `backend/app/services/experience_service.py`
- `backend/app/api/routes/experiences.py`

The model supports:

- `company`
- `role`
- `period`
- `description`
- `description_en`
- `company_url`
- `is_published`
- `display_order`

The model is registered through the existing model initialization mechanism.

The Experience router is registered in the FastAPI application.

The frontend/admin API contains Experience CRUD methods.
